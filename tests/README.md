# Проверки

- `npm test`: тесты логики и сервисов, включая регрессии аудита и генерацию иллюстраций.
- `npm run test:audit`: только регрессии ассоциаций, формы API-запросов и сервис иллюстраций.
- `npm run test:ui`: шесть браузерных наборов — синхронизация лобби/приглашения, лобби/профиль, голосование, обмен карт, финал, оформление.
- `npm run test:all`: тесты логики и сервисов, затем UI.

UI-тестам нужен Playwright: локально установленный модуль либо абсолютный путь в `PLAYWRIGHT_MODULE`. Для установленного Microsoft Edge задайте `PLAYWRIGHT_CHANNEL=msedge`. Без этих переменных используются настройки соответствующих тестов (Edge либо Chromium Playwright). Отсутствующая зависимость приводит к ошибке, а не пропуску тестов.

Пример PowerShell с имеющейся установкой Playwright:

```powershell
$env:PLAYWRIGHT_MODULE = 'C:/path/to/node_modules/playwright'
$env:PLAYWRIGHT_CHANNEL = 'msedge'
npm run test:all
```

Общий UI-раннер сохраняет скриншоты в новую временную папку, печатает её путь и не перезаписывает локальные материалы в `output/`.

Браузерные тесты выполняют код интерфейса с имитацией Supabase. Они проверяют DOM, пользовательские действия и обработку сбоев, но не подтверждают сетевую работу production. `lobby-database.sql` — отдельный интеграционный тест для подготовленной базы с миграциями; стандартные команды его не выполняют и живую базу не изменяют.
